Test plan: guests, passwords, payments and the map

Everything shipped since the bug batch, in the order it makes sense to test. Tap the box on each case to mark it passed or failed — twice for failed, a third time to clear. Your run is saved in this browser, so you can close the page and come back to it.

0 passed 0 failed 0 left

Do these two things first

1. Take the update. The app never polls for updates — it only checks when it launches or returns to the foreground, and then you have to tap the prompt. Swipe the app away completely, reopen it, and accept the update. The notes should mention confirming payments.

2. Check the server deployed. Render should be green on the latest commit to main. Every guest, payment and map test below talks to it — if it hasn't deployed, they will all fail for the same reason and tell you nothing.

What you'll need

A landlord account with at least one property and one room with a free bed, a tenant account you can sign in as, and a property code to hand. Two phones make the guest and payment sections much easier, but one works if you sign in and out. The seeded demo landlord account is fine for all of this.

Cases marked key are the ones that were broken or missing — if you only have ten minutes, do those.

A

Joining as a guest

10 cases

This used to be a lie: the button kept your property code, then sent you to the full registration form, so the person it was aimed at — someone standing in the building who wants in now — still had to invent a name, an email and a password. It should now ask for a phone number and a photo of an ID, and nothing else.

  1. A1

    On the tenant sign-in screen, tap Join as a guest.

    A two-step screen opens asking for a property code first. No account form anywhere.

  2. A2

    Enter a property code that doesn't exist and continue.

    Refused with a message naming the problem. You stay on step 1.

  3. A3

    Enter a real property code.

    Advances to step 2 and names the property you're joining, so you can tell you typed the right code.

  4. A4

    Type a 9-digit phone number.

    Rejected — a mobile number is 10 digits. Submit stays unavailable.

  5. A5

    Fill in a valid phone but attach no ID photo.

    Can't submit. The ID is required, and the screen says so rather than failing silently.

  6. A6

    Add a government ID photo (camera or gallery) and submit. key

    You are signed in immediately as a guest. You were never asked for a name, an email or a password.

  7. A7

    Find your guest ID in the profile tab and write it down.

    A six-character code shown as GUEST ID · XXXXXX. You need it for B and C.

  8. A8

    On the landlord account, open the bell.

    The request is listed, named Guest XXXXXX, with the phone number and a way to see the ID they uploaded.

  9. A9

    Accept them into a room.

    They appear in People. On the guest's phone, the property and room now show under My place.

  10. A10

    Try joining as a guest again using a phone number that already belongs to a full tenant account. key

    Refused outright. A guest must never be able to reach an existing account by typing its phone number.

B

Signing back in as a guest

5 cases

A guest has no email and no password, so the guest ID plus the phone number is the whole credential. Both halves have to be required, and neither should be guessable in bulk.

  1. B1

    Sign out of the guest account, then choose to sign in with a guest ID.

    A screen asking for the guest ID and the phone number. No password field.

  2. B2

    Right phone, wrong guest ID.

    Refused, without hinting which half was wrong.

  3. B3

    Right guest ID, wrong phone.

    Also refused. The code alone is not enough.

  4. B4

    Both correct.

    Signed straight in, with the same property and room as before.

  5. B5

    Type the guest ID in lower case.

    Still works — the field upper-cases it. Nobody should be locked out by a keyboard.

C

The landlord as the recovery path

7 cases

There is no password reset for an account with no email, so if a guest changes phones the landlord is the only way back in — they hold the government ID that person uploaded, and can check a face against it. This is brand new, and its failure mode is a credential appearing on screen when it shouldn't.

  1. C1

    As the landlord, open the guest from People and scroll to the bottom. key

    A GUEST SIGN-IN ID card, with the code hidden behind dots — not readable yet.

  2. C2

    Read what the card says before you reveal anything.

    It explains that this person has no email or password, and that you are the only one who can give them the code.

  3. C3

    Tap Show guest ID.

    The real code appears, and matches exactly what you wrote down in A7. The wording changes to tell you to check their face against the ID on file first.

  4. C4

    Tap the copy button.

    A confirmation that it copied, and pasting anywhere gives the code.

  5. C5

    Tap Hide.

    Back to dots.

  6. C6

    Go back and open a normal tenant — someone with an email and password.

    No guest card at all. Not an empty one, not one showing dots — absent.

  7. C7

    With two guests: reveal the first one's code, go back, open the second. key

    The second one's code is hidden. Revealing one person must never leave the next person's credential already on screen.

D

A guest completing their profile

8 cases

This is the upgrade from "guest at one property" to a real account that travels. It should hand over a working email and password, retire the guest code, and stop the landlord seeing them as Guest XXXXXX for ever.

  1. D1

    As the guest, open the profile tab.

    A card saying you are here as a guest, showing the guest ID, why finishing matters, and how your landlord currently sees you.

  2. D2

    Tap Complete my profile.

    Asks for a name, an email and a password. Nothing you already gave is asked for again.

  3. D3

    Try a password shorter than six characters.

    Can't submit.

  4. D4

    Try an email that already belongs to another tenant, then one that belongs to a landlord.

    Both refused, each saying which kind of account already has it.

  5. D5

    Submit a valid name, email and password.

    Confirms you can now sign in with the email and password.

  6. D6

    Sign out and sign in with the new email and password.

    Works, and everything — room, documents, payment history — is still there.

  7. D7

    On the landlord account, open that person again. key

    The guest sign-in ID card is gone entirely, and their real name has replaced Guest XXXXXX in People.

  8. D8

    Back on their phone, look at the profile tab.

    The guest card is gone. Nothing still nags them to finish something they've finished.

E

Forgot password, end to end

10 cases

Two steps: a six-digit code by email, then a new password. The code always goes to the account's own registered address, never to whatever was typed in the request, so a reset can't be redirected. E9 is the one that was crashing.

  1. E1

    Tap forgot password and enter a mobile number that isn't registered.

    Told plainly that no account is registered with those details — not a fake success.

  2. E2

    Enter a registered mobile number, not the email.

    Accepted, and it tells you which partly-hidden email address the code went to.

  3. E3

    Open that inbox.

    A six-digit code arrives, from the no-reply identity, saying it expires in 15 minutes.

  4. E4

    Enter a wrong code.

    Refused as invalid or expired. You stay on the step.

  5. E5

    Right code, but a new password under six characters.

    Refused, and says the minimum.

  6. E6

    Right code and a valid password.

    Success, and it points you at signing in.

  7. E7

    Sign in with the new password, then try the old one.

    New works. Old is refused.

  8. E8

    Go through forgot password again and re-enter the code you already used.

    Refused. A code is spent once.

  9. E9

    With a guest account that hasn't completed a profile, tap forgot password and enter the guest's phone number. key

    A clear message that this is a guest account with no password, telling them to sign in with their guest ID and phone instead. Not "Server error. Please try again." — that was the bug.

  10. E10

    Do E2 to E7 again on the landlord sign-in screen.

    Same behaviour. A code issued for one account type must never reset the other, so a landlord code should not work on a tenant account with the same email.

F

Confirming or rejecting a claimed payment

13 cases

Until now a tenant could tap "I've paid" and nothing in the app could ever answer it — the claim sat there counting toward nothing while every screen still called them overdue. Confirming is the moment the money becomes real: it counts toward your totals and moves their next rent date, which is what clears the month.

  1. F1

    As a tenant, mark rent as paid for exactly the rent amount, with a past date and a reference number.

    Told it's been sent to the landlord and clears the month only once they confirm. Your dues do not drop yet.

  2. F2

    Switch to the landlord and look at the bell. key

    The number went up by one. Declared payments count on the bell alongside people asking to join.

  3. F3

    Open the bell and read the order of the rows.

    A payments row, sitting above "tenants are overdue" — deliberately, since the person claiming may be one of the ones listed as overdue.

  4. F4

    Tap that row.

    A queue headed TENANTS SAY THEY HAVE PAID, with a line totalling the money claimed and not yet counted.

  5. F5

    Look at the row for the exact-rent payment.

    No amber warning on it — the amount is what was expected.

  6. F6

    Tap the row to open the decision.

    The amount is the biggest thing on screen, confirmed as matching their rent, with the date paid, the method, the reference to check against your bank statement, and how long it's been waiting.

  7. F7

    Tap Confirm payment. key

    A confirmation naming the amount and the tenant. The queue empties and the bell number drops.

  8. F8

    Now check four places: the tenant's card, the overdue list, the rent-collected figure, and the tenant's own app. key

    Their next rent date moved forward a month; they're no longer overdue; collected went up by the amount; and their own screen agrees. All four must tell the same story.

  9. F9

    As the tenant, declare a payment for less than the rent.

    In the landlord's queue that row is outlined in amber and says how much short it is — visible while skimming, without opening it.

  10. F10

    Open it and read the warning, then reject it with a note.

    It warns that confirming would credit only what they claim and leave the rest owed. After rejecting, the due date does not move.

  11. F11

    Look at the tenant's own payment history.

    The claim is still listed and marked rejected — it didn't silently vanish — and they can see the reason you gave.

  12. F12

    Declare a cash payment with no reference number, then open it as the landlord.

    The reference row is absent altogether — not present showing a dash.

  13. F13

    Clear the queue, then open it again.

    Says there's nothing to confirm, and explains that nothing counts toward your totals until you confirm it.

G

Putting a property on the map

12 cases

The landlord drops a pin, the address fields fill themselves in, and the tenant gets a route to their own front door. The map is drawn from tiles rather than a native map component, so it can arrive over the air — G2 is how you tell the MapTiler key actually reached the app.

  1. G1

    Edit a property and find the pin row.

    A row offering to pin it on the map, showing the current coordinates if it already has one.

  2. G2

    Open the picker and look at the top of the map. key

    No amber "development tiles" banner. If it's there, the MapTiler key didn't reach this build.

  3. G3

    Drag the map around, and pinch or use the buttons to zoom.

    The map moves under a pin that stays dead centre, and the coordinates update as you go. Tiles keep loading.

  4. G4

    Search for a landmark near the property.

    Results appear over the map after a moment's pause — not one request per keystroke. Tapping one jumps the map there.

  5. G5

    Tap Use my current location the first time. key

    The phone asks for location permission, with the map and the reason visible behind it. Allowing moves the pin to where you're standing.

  6. G6

    Deny location, then tap it again.

    A message saying location is off and pointing at phone settings — and dragging the map still works. No dead button, no crash.

  7. G7

    Place the pin on a real building and tap Use this location. key

    Back in the form with the street, locality, city and pincode filled in from the place you picked — you don't have to type them.

  8. G8

    Correct one of those fields by hand — say the flat number.

    Your typing sticks. Auto-fill is a starting point, not a lock.

  9. G9

    Save, leave the property, and come back to it.

    The pin is still there and a Directions button is offered instead of an invitation to pin it.

  10. G10

    Tap Directions.

    Your maps app opens with a route to that exact point — not a search for the address text.

  11. G11

    As a tenant of that property, open My place.

    A Directions button on the property card, routing to the building the landlord pinned.

  12. G12

    Now look at a property that has no pin, from both sides.

    The tenant is told their landlord hasn't pinned it yet — no button to a guessed location. The landlord is invited to pin it, and told why.

H

Things that could have broken

6 cases

The sign-in check that every authenticated request passes through was rewritten, and two columns changed shape. None of this should be visible — which is exactly why it's worth a glance.

  1. H1

    Sign in as the landlord and load the dashboard. key

    Normal sign-in, and every figure loads. No "not authorized" and no server error.

  2. H2

    Open the app on a device that was already signed in before today's deploy. key

    Still signed in. Nobody was logged out by the change to how tokens are checked.

  3. H3

    Record a payment yourself, as the landlord, against a tenant.

    Saved straight away with no confirmation step — it's your own statement about your own money — and their next rent date still moves.

  4. H4

    Accept one join request and decline another.

    Both still work, and the bell number drops each time.

  5. H5

    Switch the theme between light, dark and system.

    Everything follows, including the new payment queue and the guest ID card.

  6. H6

    Open a maintenance ticket and send a reply.

    The thread loads and the message posts. Untouched by this work, but it shares the same auth path.

One thing you can't check by tapping

The 90-day guest session. Guests used to be signed out every seven days and had no way back in except a code they never wrote down. That's now ninety days — but only for tokens issued after the deploy, and proving the old behaviour is gone would mean waiting eight days for it not to happen. A guest who was already signed in keeps their old seven-day session until it runs out and they sign in again. Treat it as verified by the server tests rather than by hand.

Expected gaps — don't report these as bugs

An ex-guest gets a confusing refusal. When a tenancy ends the guest code is retired, so someone who left and still has their old code is refused without being told they've left the property. Known, small, not yet fixed.

No guest notice on the dashboard. The prompt to finish a profile is only in the profile tab so far, not on the home screen.

No receipts screen. A tenant can't yet open a confirmed payment and get a rent receipt — that's the next piece of work.

When something fails, the useful details are: which case, what you saw instead, and whether it failed every time or just once. A screenshot of the actual screen beats a description of it.

Anything in group F or G that fails on every tenant and property at once is far more likely to be the server not having deployed than a bug in the app — check that before going case by case.
